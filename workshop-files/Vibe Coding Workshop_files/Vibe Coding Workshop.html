The idea
What is
Vibe Coding?
Building real software by talking to AI in plain language. You describe what you want. It writes the code, fixes the errors, and ships the thing.
⚡
The tech is evolving extremely fast

There are dozens of ways to build the same thing. The tools we use today may be irrelevant in six months. That's not a problem — it's the point. We're learning the approach, not a specific toolchain.

🔭
This is a sneak peek at the current state

What you'll see today represents where AI-assisted development is right now — a moving target. What matters is developing intuition for how to work with it.

🧠
You're learning how to think in products

Not just "build a button" — but scoping, sequencing, shipping. The same thinking that makes a great PM or designer makes a great vibe coder.

🗺
You'll discover platforms that change everything

Vercel, Railway, Clerk, Expo, Convex — tools built for exactly this kind of fast, AI-assisted building. Today you'll touch most of them.

Six months ago this required years of training. Today it requires clarity of thought — a skill you already have.

Ground rules
Three rules
for the day
1
Scope ruthlessly

3 features max. Cut everything else. You can always add more after you ship — but you can't ship what isn't done. New ideas mid-build go on a "later" list, not today's scope.

2
Done means a live URL

Not "almost working". Not "it works on my machine". A shareable link anyone can open from anywhere in the world.

3
Data access is limited

You can build internal tools for Anghami — but we won't have access to production data today. Build with dummy data or manual input, and connect the real sources later.

2

Talk to Claude — Chat, not Code

Open claude.ai (not Claude Code yet). Tell it your idea as elaborately as possible. Then say:

Send this message
I want to build [describe your idea in as much detail as possible]. I'm a non-engineer and I have one day to build and deploy this using Claude Code. I want your help to think this through, then we need to come up with a product requirements document and a brief to send to Claude Code with a list of milestones and tasks.

Work through the conversation. Answer its questions. Push back, refine the idea, cut what's unrealistic. By the end you should have a clear PRD and a task brief you're happy with.

3

Create your project folder

Create a folder on your desktop (name it after your project). Inside it, create two files from what Claude just gave you:

📄
PRD.md Your product requirements document — what you're building, for whom, what's in scope, what's cut.
💬
BRIEF.md The message you'll send to Claude Code to kick off the build — your milestones and tasks list.

Now you're ready to open Claude Code and hand it the folder.

10:45 — Planning session
Planning with
Claude Code
Open the Claude desktop app, go to the Code tab, and point it at your project folder. Then send it your brief from BRIEF.md. It will read your files, ask clarifying questions, and propose a plan. This is the most important part of the day — don't rush it.
1

Send your brief and answer its questions

Paste the contents of BRIEF.md. Claude Code will ask questions and propose an approach. Adjust, push back, and confirm before it writes a single line of code. Get the plan right here.

2

Add these instructions to the plan

Once you've agreed on the approach, add the following to your message:

Paste this into Claude Code during planning
Before you start building, please follow these instructions:

— Deploy target: Vercel for the frontend, Railway for the backend/server. Set up configuration files for both from the start.
— Maintain an internal task list and keep it updated as you complete each step.
— Set up a Git repository from the beginning. Commit after completing each task.
— Maintain a CLAUDE.md file with your core instructions. Keep it short and straight to the point.
— You are a product designer with a PhD in human-computer interaction, and a super senior principal engineer building architecture that scales and is bug-free. Design and build accordingly.
3

Conditional: if your project needs login

If your app requires user accounts
Use Clerk for authentication

Tell Claude Code: "This project requires user login. Use Clerk for authentication — set it up as part of the scaffold." Clerk handles sign-up, sign-in, and session management out of the box. No building auth from scratch.

4

Conditional: if your project is a mobile app

If you're building for iOS / Android
Use Expo instead of a web framework

Tell Claude Code: "This is a mobile app. Use Expo (React Native) as the framework. Set up the project with Expo Router." Expo lets you build and preview the app on your phone without App Store submissions.

11:30 — Build blocks
While building
You're in Claude Code. It's running. Here's how to stay unblocked and make progress.
→
Be specific, not vague

"Add a form with a title field and a submit button that saves to the database" beats "make a form". The more precise the instruction, the better the output.

→
One thing at a time

Finish one task, check it works, then move on. Don't ask for five things in one message — it causes tangled output that's hard to review.

→
Use plan mode for big changes

Before any large refactor or new feature, ask Claude to "plan this out first without touching any files". Review the plan, then proceed.

→
Scope creep kills ships

New ideas mid-build go on a "later" list — not today's scope. Ship what you planned. Add more after you have a live URL.

When things break
Paste the exact error — never describe it

When something breaks, copy the full error message from the terminal or browser console and paste it directly into Claude Code. Don't summarise, don't paraphrase. The exact text is what Claude needs.

Error prompt — copy and use when needed
Something went wrong. Here's the exact error:

[paste full error here]

Please fix it without changing anything else that's already working.
When you're stuck and nothing makes sense
I think we've gone off track. Please stop, review the current state of the project, compare it to CLAUDE.md and our original plan, and tell me what's broken and what the best path forward is.
Check progress at any time
What's the current state of the project? What's been completed, what's in progress, and what still needs to be done before we can deploy?
15:30 — Deploy
Deploy
Two platforms. Vercel hosts your frontend — the part users see. Railway hosts your backend — the server, APIs, and anything that runs code. Together they give you a fully live app.
Vercel — your frontend
Vercel is where your web app lives. It takes your code from GitHub and turns it into a public URL in about 60 seconds. Every time you push new code, it automatically redeploys. Free tier is more than enough.
1
Create a free account

Go to vercel.com and sign up using your GitHub account.

2
Import your GitHub repo

Click "New Project" → select your repository → click Deploy. Vercel auto-detects the framework.

3
Add environment variables

Go to Project Settings → Environment Variables. Add any keys Claude Code told you about (API keys, database URLs). Redeploy after saving.

4
Get your URL

Your app is live at yourproject.vercel.app. Copy it and share it.

Railway — your backend
Railway hosts your server — any code that runs on demand, handles API requests, processes data, or connects to a database. If your project is purely a frontend with no server logic, you may not need this today. If you do, Railway is the easiest way to set it up.
1
Create a free account

Go to railway.app and sign up using your GitHub account.

2
Deploy from GitHub

New Project → Deploy from GitHub repo → select your repo. Railway detects your server automatically.

3
Add environment variables

Go to your service → Variables. Add the keys your backend needs. Railway restarts automatically.

4
Copy the public URL

Railway gives your backend a public URL. Paste it into your Vercel environment variables so the frontend can talk to it.

Conditional setups
If your app has user login
Clerk — environment variables

Claude Code will generate Clerk keys during setup. Add them to both Vercel (frontend) and Railway (backend) under environment variables: NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY and CLERK_SECRET_KEY.

If you built a mobile app
Expo — publishing your app

Run npx expo publish or use Expo Go to preview on your phone. For a shareable link, use EAS Build: ask Claude Code to "build this for Expo and give me a shareable preview link".

Go deeper
Explore on
your own
Today is just the beginning. Claude and the ecosystem around it have capabilities most people haven't discovered yet. These are worth exploring on your own time — each one meaningfully expands what you can build and how fast you can build it.
🧩
Skills

Reusable instruction sets that make Claude better at specific tasks — writing in your style, following your design system, or coding in your preferred patterns. Think of them as saved expertise for specific jobs.

🔌
Plugins

Extend Claude Code with integrations — connect it to your tools, databases, and APIs. Plugins let Claude take actions beyond your local files: querying a service, calling an API, or reading from a third-party source.

🤖
Agents

Autonomous Claude instances that run a task end-to-end without you watching. You describe the goal, the agent works out the steps, executes them, and reports back. Great for longer tasks that don't need input at every step.

🧪
Playground

Experiment directly with Claude models at console.anthropic.com — test prompts, tweak parameters, and explore what the model can do before you build it into a product.

🖥
Claude Cowork

An autonomous background agent that works on long, complex tasks in a cloud VM while you do other things. Give it a research, writing, or file-processing job and check back when it's done. No terminal needed.

📱
Dispatch

Send tasks to Claude from your phone and it picks them up on your desktop. Start something on the go, have it running by the time you sit down. Bridges mobile and desktop in one continuous conversation.

⏰
Scheduled Tasks

Set Claude to run something on a schedule — daily, weekly, at a specific time. Useful for recurring reports, automated checks, digest generation, or anything you currently do manually on a cadence.

🌐
Claude in Chrome

A browser extension that lets Claude read, navigate, and interact with web pages alongside you. Great for research, automating repetitive browser tasks, and acting on what's on your screen.

🔗
MCPs — Model Context Protocol

A standard that lets Claude connect to any external tool or data source — your database, Slack, Google Drive, Notion, a custom API. Think of it as a universal plug for giving Claude access to the things it needs to do real work. If you can describe a data source, you can probably build an MCP for it.
